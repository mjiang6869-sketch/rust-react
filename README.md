# Rust Crypto — 币安合约做市研究平台

Rust + React 的币安 USDⓈ-M 永续合约做市研究平台。本地运行，默认模拟盘。

## 这个项目解决什么问题

除了回测与模拟盘，它要解决一件**币安原生做不到**的事：**一个点位挂单、同时挂
分批止盈与止损**。

币安 USDⓈ-M 没有 OCO，也没有 bracket 单。支持的条件单只有：

```text
STOP / STOP_MARKET / TAKE_PROFIT / TAKE_PROFIT_MARKET / TRAILING_STOP_MARKET
```

一张单只能对应一个数量与一个触发价。所以下面四件事必须由客户端实现：

1. 一个点位挂单，同时挂分批止盈与止损
2. 分批止盈（例如 40%/30%/30%），三张单分开挂、分别成交
3. 保本止损：浮盈后把止损推到入场价，需要撤单重挂
4. 止损成交后撤销未成交的止盈单（没有 OCO 自动做这件事）

## 快速开始

需要 Rust 稳定版、Node.js 20+、pnpm、curl。

```sh
git clone <repo> && cd rust-crypto
./scripts/run.sh
```

首次运行会自动安装前端依赖并编译 Rust 服务（较慢），之后几秒内启动。

打开 `http://127.0.0.1:5174`。

### 脚本命令

```sh
./scripts/run.sh              # 启动（默认）
./scripts/run.sh restart      # 重启
./scripts/run.sh stop         # 停止
./scripts/run.sh status       # 查看进程与健康状态
./scripts/run.sh logs         # 跟踪日志（Ctrl-C 退出，不停服务）
./scripts/run.sh build        # 只构建，不启动
```

脚本会自己发现 `cargo` 与 `pnpm` 的位置——从 GUI/IDE 启动的 shell 通常不
继承登录 shell 的 PATH，不需要手动 `export`。

### 界面

左侧导航四个页面：

| 页面 | 内容 |
| --- | --- |
| 总览 | 权益与盈亏、成交模型与费率、在途订单 |
| 交易行情 | K 线图表 + 盘口 + 自动化做市 + 手动下单面板 |
| 数据管理 | 下载任务、覆盖查询、缺口 |
| 回测 | 参数、运行、M0/M1 对比 |

顶栏的模式、连接、费率来源告警**在任何页面都可见**——「以为在模拟盘其实在
实盘」是交易软件最严重的失败模式，任何页面都不该有看不到模式的时刻。

#### 图表数据的来源与边界

图表读的是**币安公开 REST**，不是本地归档。原因很简单：你打开界面时本地
通常什么都还没下载。代价是图表覆盖的区间不等于回测覆盖的区间，所以接口
响应里带 `source` 字段，界面必须把它显示出来。

回测**永远**读本地归档——那才是可复现、可校验的那一份数据。

### 环境变量

```sh
RUST_CRYPTO_SYMBOL=ETHUSDC         # 交易对
RUST_CRYPTO_MODE=PAPER             # PAPER（默认）或 LIVE
RUST_CRYPTO_DATA_ROOT=./data       # 数据目录
RUST_CRYPTO_BIND=127.0.0.1:8080    # 后端监听地址
RUST_CRYPTO_FRONTEND_PORT=5174     # 前端端口
RUST_CRYPTO_BINANCE_MARKET_URL     # 行情 base URL，默认币安生产网
RC_RELEASE=1                       # 用 release 构建（运行更快）
```

`RUST_CRYPTO_BINANCE_MARKET_URL` 只能指向白名单内的域名（币安生产网与测试
网）。测试网与生产网的行情**不同**，误指会让图表显示的价格与将要下单的
价格不一致。

运行目录是 `.runtime/`（日志与 PID），不写入 Git。

盘口与成交流的推送只接币安生产网（`wss://fstream.binance.com`）。
`RUST_CRYPTO_BINANCE_MARKET_URL` 指向非生产地址时推送不启用，界面会显示
原因——测试网的推送入口不同，混用会让盘口与 K 线来自两个市场。

### 币安限流

币安 REST 按 IP 计权重，USDⓈ-M 上限 2400/分钟（以 `/fapi/v1/exchangeInfo`
的 `rateLimits` 为准）。收到 429 后继续请求会升级成 418 封禁。本项目的
做法：

- 后端解析 `Retry-After`（秒），冷却期内**所有**上游请求（REST 与推送握手）
  都不发，并把 429 + `Retry-After` 透传给前端；前端据此暂停并显示倒计时。
- 公开行情 REST 有按参数的共享缓存与单飞：多开标签页不会线性放大上游请求。
- K 线、盘口与成交流均走推送，正常看盘不再定时请求 REST。
  K 线首次加载/切换周期读取 499 根历史（权重 2），断线重连或检测到缺口时
  再补齐；同一交易对、同一周期共享上游连接。历史响应不会覆盖更新的推送。

- 上游失败的日志带方法、路径、HTTP 状态、币安错误码、`x-mbx-used-weight-1m`
  与冷却时长；不记录查询串（签名请求的查询串里有签名）。

## 当前状态

**默认模拟盘。** 真实下单能力需要显式 `RUST_CRYPTO_MODE=LIVE` 且通过三个
前置条件（用户数据流连接、账户对账、显式 ARM）。

| 能力 | 状态 |
| --- | --- |
| 历史数据下载与转换 | ✅ |
| 回测（含反自欺指标） | ✅ |
| 手动下单（分批止盈 + 止损 + 保本） | ✅ |
| 数据管理与覆盖查询 | ✅ |
| K 线图表 | ✅ 历史 REST 初始化，当前 K 线走原生 WS 推送；断线后补齐 |
| 盘口 | ✅ 币安行情推送，后端按交易对共享一条上游连接 |
| 逐笔成交 | ✅ 只走推送，供引擎撮合与「最新价」；界面不再单列最近成交，也不再用 REST 拉成交 |
| 引擎接实时行情（模拟盘能成交） | ✅ 逐笔成交 + 1m 收盘 K 线，启动时后台预热；见下方限制 |
| 自动化做市（模拟盘） | ✅ 默认关闭，交易行情页可开关与配置参数；见下方说明 |
| 实盘下单 | ⚠️ 客户端已实现，尚未接入事件循环 |

**模拟盘的行情来源**：服务启动后在后台订阅币安 `RUST_CRYPTO_SYMBOL` 的
逐笔成交与 1m K 线（与图表共用同一条上游连接），逐笔喂给引擎；同时用 REST
拉 120 根 1m K 线预热策略窗口（权重 2，走共享冷却，失败会退避重试）。启动
过程不等这些完成——离线时服务照常起来，界面显示行情未连接。

引擎只在**成交流与 K 线流都在线**时视为行情已连接；任一断开即暂停开仓并撤掉
在途开仓单。已知限制：

- **断线期间的成交不补**：重连后从新的成交接着判定，断线那段时间里本该触发
  的止盈/止损会被漏判。断线补成交暂未实现
- **引擎状态不落库**：重启后持仓、在途单、已实现盈亏全部清零
- 只接一个交易对；只接币安生产网（`RUST_CRYPTO_BINANCE_MARKET_URL` 指向非
  生产地址时引擎收不到行情，日志会给出警告）

图表与引擎读的是同一份上游推送，但走两条独立的消费通路：图表看节流后的最新
视图，引擎按顺序收每一笔成交（M1 成交模型需要逐笔数据）。

### 自动化做市

交易行情页右侧的「自动化做市」面板控制策略是否自动下单（策略为区间做市
`range_maker`）：

- **默认关闭，重启后也是关闭**——不会因为重启自动恢复风险状态。关闭时行情照常
  接入，但只有手动下单
- **只在模拟盘运行**：实盘模式下拒绝开启，切到实盘会自动关闭
- 可配置回看根数、止盈距离、止损缓冲、仓位比例、杠杆、挂单有效期、只做多/只做空。
  参数由后端校验，回看根数不超过引擎 K 线窗口（120 根）
- 改参数从下一根 1m K 线收盘开始生效，并撤掉策略当前的在途开仓单（它是按旧参数
  算的）；关闭只撤策略的开仓单，不动手动单与已有持仓的止盈止损
- 保本 / 移动止损：模拟盘引擎暂不执行，所以暂不开放
- 在途开仓单（策略或手动）出现在「当前委托」里，标明来源，可以撤单
- 已知限制：止盈止损单不在「当前委托」中显示（持仓卡片里可以看到）

## 架构

Workspace 结构，依赖方向严格向内：

```
crates/
├── domain/       零 I/O 领域层
│                 量化 · 合约规则 · 行情事件 · 策略接口 · 风控
│                 订单状态机 · 保护单规划器 · 持仓-保护单一致性 · 运行模式
├── data/         历史数据
│                 下载器 · 台账 · 定点编码 · Parquet 转换 · 回放
├── sim/          撮合与回测
│                 成交模型 M0/M1 · 成交带 · 反自欺指标 · 回测引擎
├── store/        热状态持久化（SQLite）
├── strategies/   策略实现
├── exchange/     币安客户端（签名 · 合约规则 · REST · 公开行情）
├── engine/       编排层（模拟盘引擎）
├── api/          HTTP + WebSocket
└── cli/          命令行（download / backtest / coverage）
apps/server/      服务端入口
frontend/         React 界面
```

**`domain` 的零 I/O 是硬约束**，CI 校验：

```sh
cargo tree -p domain | grep -E 'tokio|reqwest|duckdb|axum'   # 必须无输出
```

这条约束换来的是：回测、模拟盘、实盘共用同一套订单生命周期与保护单数学，
全部可用纯函数测试覆盖。

### 为什么回测的成交模型是核心

零手续费做市下，单笔毛利润就是止盈距离（约 4bp）。没有价差缓冲、没有返佣、
没有逆向选择垫。**成交模型乐观 10% 不是让 P&L 差 10%，而是可能翻转符号**：
亏损的交易（突破把你扫掉）建模得近乎完美，盈利的交易（需要对手方主动吃你
的挂单）被建模成免费。

所以回测必须同时跑两个模型并报告差异：

| 模型 | 含义 |
| --- | --- |
| `M0` | 上界：wick 触价即全额成交。**不现实，仅作对照** |
| `M1` | 保守下界：要求真实成交发生在我们的价位，且由正确方向的主动单驱动 |

回测报告给出四个反自欺指标：盈亏平衡成交率、markout（逆向选择检测）、
止损裸露分析、费率贡献。

**排队位置无法从币安任何免费归档还原**——`aggTrades` 与 `trades` 都只有
`is_buyer_maker` 一个方向标志，没有订单 ID；`bookTicker` 已于 2024-04 停更。
所以 M1 的「排在队尾」是唯一可能的选择，不是保守近似。

## 数据

历史数据从 `data.binance.vision` 归档下载（CDN 静态 ZIP，支持 Range 断点续传）。

| 数据集 | 覆盖 |
| --- | --- |
| `klines/1m` | 2024-01 起 |
| `aggTrades` | 2024-01 起，成交模型与 markout 的数据源 |
| `markPriceKlines/1m` | 2024-01 起，强平距离 |
| `fundingRate` | 完整，持仓成本 |
| `trades` | **不使用**：字段与 aggTrades 同构，体积 2.5 倍 |
| `bookTicker` | **已停更**，不可用 |

数据落盘为 Parquet（Hive 分区），DuckDB 直接 SQL 查询。下载台账记录每个
分区的状态与校验和，重跑会跳过已完成的分区。

## 安全

- API 只绑定回环地址，**无法通过配置绕过**。它没有登录认证。
- API Key 从环境变量读取，不落盘、不打印。`Credentials` 的 `Debug` 是手工
  实现的，只显示「已隐藏」。
- 出场单**全部**是 reduce-only 的 GTX 限价单，不用市价单兜底。
- 网络超时与 5xx 归类为「状态未知」，必须先查询对账，绝不直接重试提交。
- 实盘要求用户数据流连接、账户对账、显式 ARM 三个条件同时成立；断线或不
  一致会**自动解除武装**；重启后不恢复武装状态。
