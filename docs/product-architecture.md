# 自动交易桌面端架构契约

## 目标

项目目标是一个 Electron 桌面端自动交易研究平台，统一提供实时行情、回测、策略运行、图表标注、会话式 AI 分析和真实交易执行。第一交易所为币安 USDⓈ-M，产品继续覆盖 USDT/USDC 本位加密永续和已识别的 TradFi 永续。

Rust 是交易域的唯一事实来源。Electron renderer 只负责展示、交互和图表，不直接访问交易所、不读取凭据、不构造订单。

## 进程边界

```text
Electron main
  ├─ 启动并监管 Rust engine sidecar
  ├─ 管理窗口、更新、桌面通知和本地安全存储
  └─ 只通过受限 IPC 与 renderer 通信

React renderer
  ├─ K 线、订单、持仓、回测和 AI 会话界面
  └─ 只调用 preload 暴露的 typed API

Rust engine
  ├─ 行情与交易所规则
  ├─ 策略、回测、风险和账户状态
  ├─ Maker-only 订单状态机
  ├─ PAPER/LIVE 隔离与用户数据流对账
  └─ 本地持久化和事件回放

AI service
  ├─ 接收只读行情、指标、持仓和策略上下文
  ├─ 返回分析文本和结构化图表标注
  └─ 不能直接提交、修改或撤销订单
```

## 交易不变量

1. 启动模式必须显式为 `PAPER` 或 `LIVE`，默认是 `PAPER`。
2. `LIVE` 只能使用经过 allowlist 校验的交易所 endpoint，并在启动时完成账户、费率、合约规则和用户数据流检查。
3. 所有开仓、止盈和止损订单都必须是限价 Maker-only 订单。
4. 订单如果会立即吃单，必须拒绝提交；禁止改成市价单或自动降级为市价单。
5. 止损触发后仍是限价保护单。未成交期间保持只减仓、告警和人工可见状态。
6. 请求超时、撤单未知、断线重连和重复事件都必须先查询并对账，不能直接重复提交。
7. 订单、成交、手续费、资金费、保证金和 PnL 都必须带结算资产。
8. AI 输出只能产生建议和标注，确定性的风险闸门才允许产生订单意图。

## 领域接口

策略统一输出 `Signal` 或只读 `AnalysisAnnotation`，不直接调用交易所：

```text
MarketData -> Strategy -> OrderIntent -> RiskGate -> ExecutionAdapter
                                  \-> ChartAnnotation / AI context
```

`ExecutionAdapter` 至少需要支持：提交 post-only 限价单、查询订单、撤单、查询账户、订阅用户数据流和恢复未完成订单。回测实现同一套 `OrderIntent` 和成交事件，但使用可配置的 K 线或订单簿撮合器。

## 策略与 AI

首批策略包括现有失败突破回踩策略、缠论结构分析和趋势线/支撑阻力分析。缠论和 AI 输出统一为结构化标注：周期、点位、笔/线段/中枢、趋势方向、置信度和来源。标注可以绘制在 K 线上，但不能改变 Rust 中的持仓或订单状态。

会话分析请求必须携带固定时间窗口、数据集标识、指标快照、当前策略版本和资产/持仓上下文。模型返回的自然语言需要和结构化标注一起保存，方便复盘；模型不可访问 API Secret，也不可直接调用下单工具。

## 实施顺序

1. 将现有 `PaperEngine` 抽到统一交易域接口，补齐 `schema_version`、事件记录和模式字段。
2. 建立 Electron main/preload/renderer 外壳，Rust 作为 sidecar 运行。
3. 实现 Binance 公开行情、用户数据流和 Maker-only 执行适配器，先完成 PAPER 对账。
4. 实现确定性回测、K 线撮合和订单簿撮合，输出交易明细、权益曲线和数据缺口。
5. 接入缠论/趋势策略与图表标注协议。
6. 接入 AI 会话分析和只读工具调用。
7. 在独立验收后开放显式 LIVE 模式；任何真实交易能力都不能由 PAPER 自动升级。
